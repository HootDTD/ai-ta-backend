# Hoot AI-TA — Architecture doc router

Read order for ANY task: this file → the relevant domain `_index.md` → 1-3 leaf
docs. Reach any source file in ≤4 hops reading ≤~500 doc-lines. Never read a
source file to understand the SYSTEM — only to make the change. To resolve a
source file to its owning doc, use `docs/index.json` (generated by the lint).

## Doc format contract

Every leaf: YAML frontmatter { `doc`, `description`, `owns` (EXPLICIT paths),
`related`, `last_verified`, `stub` }. Routers set `owns: []`. Leaf body ≤80 lines
(hard cap 150), sections in order: Interface / Data flow / Invariants & gotchas /
Env flags / Related. Index ≤60 lines: a table of leaves (one-liner + owned files)
+ a cross-cutting-invariants block + any "to change X touch Y" recipe.

## Ownership is a bijection

Every non-test `.py`/`.ts`/`.tsx` maps to exactly one leaf's `owns`. Enforced by
`scripts/docs/check_owns_coverage.py` (CI + pre-commit): uncovered, double-owned,
dangling, owns∩exclude collision, broken `related:` id, stale `_index` table, and
(on the PR path) an owned-file change that didn't bump its leaf's `last_verified`
all fail. Migrations: legacy chain → `database/legacy-migrations.md`, active chain
→ `database/supabase-migrations.md`.

## Drift contract (per-leaf, same-commit)

Before editing a source file, resolve its owning leaf (via `docs/index.json` or the
domain `_index`) and load it. Cross-cutting invariants live in the domain `_index` —
change them THERE, once. After editing, reconcile that leaf in the SAME commit and
bump its `last_verified` (the PR lint enforces this). New source file → add to a
leaf's `owns` (or new leaf + register in its `_index`) same commit; the bijection
lint fails the PR otherwise. Stale docs are worse than none.

## `_archive` is skipped by navigation

`docs/_archive/` is committed but not loaded by default; open it only to resume the
specific task whose handoff lives there.
