> **DELETION CANDIDATE (vestigial).** `draft_reply` has **zero live importers** —
> the live Apollo reply is now generated by `questioning/unified.evaluate_and_ask`.
> Documented to keep the ownership bijection total; deletion is an owner decision
> (Risk R1).

`apollo/agent/apollo_llm.py` was the confused-learner persona reply generator.

## Interface

- `draft_reply(history, kg_summary, *, problem_text=None, model=None, history_summary=None) -> str`
  — **dead** (no live caller).
- `ContextOverflowError(RuntimeError)` — raised when `_estimate_tokens` exceeds
  `_TOKEN_BUDGET` (100k). **The one still-wired symbol.**
- `APOLLO_SYSTEM_PROMPT` — the persona system-prompt module constant.
- `_estimate_tokens` — tiktoken count with a 4-chars/token fallback.

## Data flow

`draft_reply` assembled a persona system prompt + problem + KG summary + optional
`history_summary` + chat history, ran a token-budget check, then a direct
`OpenAI().chat.completions.create` (`APOLLO_MODEL` → `config.models.MAIN_MODEL`,
`temperature=0.7`). Structural anti-leak: it saw only the **student** KG (no
reference material), so it could not name an un-taught concept; its own docstring
notes "the output filter is removed in v1".

## Invariants & gotchas

- `ContextOverflowError` is registered lazily by `api.py` as a 503 handler
  (`routing/router`, imported inside `register_exception_handlers` to dodge a
  circular import) — but it is **only raised inside dead `draft_reply`**, so it is
  effectively unraisable on the live path (Appendix A #4).
- Recommendation: delete `draft_reply` and relocate `ContextOverflowError` into
  `apollo/errors.py` (`routing/errors`), OR remove the whole file plus its handler
  registration.

## Env flags

- `APOLLO_MODEL` — persona model override (dead path). `APOLLO_SYSTEM_PROMPT` is a
  module constant, not an env override.
